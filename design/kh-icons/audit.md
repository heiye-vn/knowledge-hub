# Knowledge Hub UI 图标落位分析

> 范围：`apps/web/src`（React + Ant Design 5，主色 `#1677ff`，圆角 6）
> 结论基于逐页阅读源码得出，未改动任何业务代码。

---

## 一、总体结论

现有界面的图标覆盖是**不均匀**的：

- **导航层**覆盖尚可 —— 8 个文件引用了 `@ant-design/icons`，顶栏 / 侧栏 / 工作台卡片都有图标。
- **产品最核心的差异化界面（Agentic RAG 推理过程）几乎裸奔** —— 7 类推理节点全部只有文字标签，
  节点本身是一个 10×10 的纯色圆点，**语义完全由颜色承担**（蓝=意图、紫=知识库、绿=评估通过、
  黄=需再检索、红=失败、青=联网、橙=改写、灰=思考、靛蓝=图谱）。
- **文档操作区退化成一排纯文字按钮** —— 详情页 8 个按钮、表格操作列全是 `<a>` / `<Button>文字</Button>`。

所以这套图标的价值不在于"再画 29 个通用图标"，而在于补齐 **Agent 链路** 与 **文档状态机** 两块语义空白。

## 三、P0：Agent 推理链路（最高优先级）

这是产品的技术卖点，也是当前视觉最薄弱的地方。建议做三件事：

1. **把 `.kh-trace-node` 从 10px 彩色圆点升级为 18px 图标节点**
   保留颜色作为辅助编码，形状承担主语义。改造成本极低：`TraceItem` 已经在渲染
   `<span className="kh-trace-node" />`（`ChatMessageParts.tsx:268`），只需把 `kind` 映射到图标名。

   ```tsx
   const NODE_ICON = {
     intent: 'intent', kb: 'retrieve', eval: 'evaluate', rewrite: 'rewrite',
     web: 'web', think: 'think', graph: 'graph',
   } as const

   <span className="kh-trace-node" aria-hidden>
     {NODE_ICON[kind] ? <KhIcon name={NODE_ICON[kind]} size={13} /> : null}
   </span>
   ```

2. **在每张卡片的 `.kh-panel-type` 文字前加 14px 图标**
   卡片内文字标签是用户真正在读的部分，图标放这里收益最大。

3. **给「意图识别」的三个范围开关加图标**
   知识库 = `retrieve`、图谱 = `graph`、联网 = `web`，用「实色 / 40% 透明度」表达 on/off，
   替代现在只靠 `color: #52c41a / #bfbfbf` 的文字。

配套图标（8 枚）：`intent` `retrieve` `evaluate` `rewrite` `web` `think` `answer` `cite`

## 四、P1：文档与权限操作

| 位置 | 建议 | 图标 |
| --- | --- | --- |
| 详情页「返回列表」 | 左侧箭头 | AntD `ArrowLeftOutlined`（通用） |
| 「编辑」 | 铅笔 | AntD `EditOutlined`（通用） |
| 「版本」 | 层叠 | `version` |
| 「发布」 | 上行箭头 + 地平线 | `publish` |
| 「归档」 | 收纳盒 | `archive` |
| 「删除」 | 垃圾桶 + danger 色 | AntD `DeleteOutlined`（通用） |
| 「查看原文」 | 链环 | `cite` |
| 列表行「编辑 / 发布」 | 纯图标 + Tooltip | 同上 |
| 导入区主 CTA | 上传托盘 | `upload` |
| 侧栏「我的收藏」 | 星 | `favorite` |
| 侧栏「新建文档」 | 虚线空页 + 加号 | `new-doc` |

原则：**只给"图标能替代文字"或"图标能加速扫读"的按钮加图标**。表单的「查询」「重置」
「清空」这类短动作词，加图标反而增加噪声 —— 保持纯文字。

## 五、P2：状态与空态

| 场景 | 图标 | 说明 |
| --- | --- | --- |
| 审核通过 / 导入完成 / 操作成功 | `success` | 替代 `Tag color="success"` 的纯文字 |
| 处理中 / 排队 / 流式生成 | `processing` | 配合 CSS `animation: spin 1s linear infinite` |
| 失败 / 驳回 / 校验错误 | `failed` | `Alert` 与 `Tag` 共用 |
| 403 无权查看 | `locked` | 区分于「文档不存在」 |
| 无结果 / 无会话 / 无数据 | `empty` | 配合文案做品牌空态，替换默认 `Empty` 插图 |

**注意**：`success` / `failed` 与 AntD 的 `CheckCircleOutlined` / `ExclamationCircleOutlined`
语义重复，二选一即可。建议保留 AntD 版本用于系统级提示（message / alert），
本套图标用于**业务状态徽标**，避免同一屏出现两种圆形对勾。

## 六、图谱语义

`GraphPage.tsx:216-235` 的图例目前是「色块 + 线型」，建议改为「图标 + 颜色 + 线型」三重编码：

- 文档 → `documents`（蓝 `#1677ff`）
- 实体 / 概念 → `concept`（绿 `#52c41a`）
- 标签 → `tag`（紫 `#722ed1`）
- 提及 / 关联 / 标注 → 保留现有实线 / 虚线 / 紫色虚线

这样即使黑白打印或色盲用户，也能通过形状区分三类节点。

---

## 七、哪些地方**不要**加图标

资深判断的一部分是克制。以下位置建议保持纯文字：

1. **表格列头**（标题 / 分类 / 状态 / 更新时间）—— 列头本身有对齐关系，加图标会破坏栅格。
2. **表单标签**（标题、分类、可见性）—— 图标会与必填星号抢注意力。
3. **筛选下拉的选项文本** —— Select 内部加图标需要自定义 `optionRender`，收益低。
4. **短动作按钮**（查询 / 重置 / 清空 / 取消）—— 两个字能说清的事不需要图形。
5. **Tag 内部**（分类名、团队名、权限码）—— Tag 已经足够轻量，加图标会让标签膨胀 40%。
6. **正文 Markdown 内的标题层级** —— 图标会干扰阅读节奏。

## 九、实施顺序建议

1. **第一步（收益最高）**：过程条 8 枚图标 + `.kh-trace-node` 尺寸调整 —— 只动
   `ChatMessageParts.tsx` 一个文件与 3 条 CSS，就能让产品最核心的界面成立。
2. **第二步**：文档详情页工具条 + 列表行操作 —— 收敛为「图标 + 文字」，删除用 danger 色隔离。
3. **第三步**：图谱图例三重编码 + 空态品牌化。
4. **第四步**：`FileTypeIcon` 补齐图片类型（`png` `jpg` `jpeg` `webp` `svg`），
   并修正 `extFromName` 的兜底逻辑：未知扩展名应返回中性 `file` 徽标，而不是 `md`。

每步都可独立上线，不需要一次性替换全站 AntD 图标 —— **共存完全可行**：
本套描边 1.6、AntD 线性图标视觉粗细约 1.5–1.6，同尺寸并排不会跳。
